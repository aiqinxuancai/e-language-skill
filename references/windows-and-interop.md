## 窗口与组件

易语言窗口项目由设计器中的窗口/组件树和窗口程序集代码共同组成。组件属性、事件名称和支持库组件类型都依赖实际工程，不要凭常见名称创建不存在的属性或事件。

处理窗口任务时：

1. 读取对应窗口代码页和只读 XML/组件信息。
2. 搜索控件实例名及已有事件。
3. 查询组件所属支持库的公开接口。
4. 只修改代码页；需要新增/删除控件或改变布局时使用 IDE 设计器能力。

## 事件绑定

常见事件子程序名包含窗口或控件实例名，例如：

```text
.子程序 _按钮1_被单击
```

事件绑定可能依赖内部事件索引而不只是名字。不要把事件移动到普通程序集、其他窗口或类；不要在未同步设计器元数据的情况下随意重命名控件或事件。可把通用逻辑提取到全局唯一命名的普通子程序，再从原事件中调用。

## DLL 声明流程

调用 Win32 或第三方 DLL 前：

1. 确认目标平台位数、DLL 实际路径和导出入口名。
2. 从官方头文件/文档确认原型、调用约定、返回值和错误机制。
3. 映射每个 C 类型到当前易语言环境的确切宽度。
4. 明确参数是值、指针、输入输出缓冲区、字符串、结构体还是回调。
5. 确认 ANSI/Unicode 入口及字符串终止方式。
6. 写 `.DLL命令` 与 `.参数`，保留固定字段空槽。
7. 用最小输入测试成功、失败、空值和边界长度。

不要根据函数名猜 `A/W` 后缀、字符宽度或结构尺寸。

## 类型、指针与句柄

- 经典易语言 IDE 和许多支持库以 Win32/x86 为主，`整数型` 常被用于 32 位句柄或地址，但这不是跨位数保证。
- `HANDLE`、`HWND`、指针、`WPARAM/LPARAM`、`size_t` 等必须按目标 ABI 映射。目标变化时重新审查，不要默认都是整数型。
- `BOOL` 与易语言逻辑型/整数型的映射依赖声明方式和支持库约定；按实际接口验证。
- 指针指向的内存必须在调用期间有效；保存异步指针时要保证所有权和生命周期。
- 不把对象变量或文本变量的内部表示当成稳定的 C 结构。

## 文本编码

- `FunctionA` 通常接收本地代码页/ANSI 字符串；`FunctionW` 接收 UTF-16。
- 易语言文本如何传给 DLL 取决于运行库和声明桥接。确认现有封装或使用明确的编码转换与缓冲区。
- 缓冲区长度要区分字符数、字节数和是否包含终止符。
- 返回文本的 API 要明确由谁分配、谁释放以及缓冲区是否可写。
- 中文路径、页面名和 MCP JSON 传输使用 UTF-8 时，在本地 IDE/Win32 边界显式转换，避免把 UTF-8 字节当作 GBK/ANSI。

## 自定义数据类型与内存布局

使用 `.数据类型` / `.成员` 映射 C 结构时：

- 保持字段顺序，不按可读性重排。
- 核对每个字段宽度、有符号性、嵌套结构、固定数组长度和对齐。
- 区分内联数组与指针字段。
- 结构的 `cbSize`/`dwSize` 一类字段通常要填实际字节数。
- `union`、位域、可变长度尾数组和平台相关对齐不能用普通字段列表盲目映射；优先使用成熟支持库封装或字节集手工编解码并写测试。

## 回调

- 使用 `&回调子程序` 取得地址；需要数值地址时按当前平台使用已验证的转换。
- 回调的参数、返回值和调用约定必须与原生声明完全一致。
- 回调期间不要让承载代码或相关对象提前销毁。
- 原生线程触发的回调不能直接操作非线程安全的 IDE/UI 对象；把数据投递回主线程。
- 捕获回调上下文时使用显式句柄或索引，不假设存在闭包。

## 线程与生命周期

- 支持库可能提供线程、同步、网络或异步命令，这些是依赖 API，不是语言固有能力。
- UI 对象通常只能由创建它的线程访问。
- 共享全局变量和类实例需要同步；先搜索项目既有锁或消息机制。
- DLL 返回的句柄、内存、窗口、文件和网络对象必须走匹配的释放函数。
- `_销毁`、窗口销毁事件或程序退出路径应解除回调、停止工作线程并释放资源。

## 互操作检查表

- [ ] 位数与调用约定正确。
- [ ] DLL 名和入口名真实存在。
- [ ] 返回值、错误码及 `GetLastError` 使用时机正确。
- [ ] 所有参数宽度、方向和可空性正确。
- [ ] 文本编码、缓冲区单位和终止符正确。
- [ ] 结构大小、对齐、数组和嵌套布局正确。
- [ ] 指针、回调和异步数据生命周期正确。
- [ ] UI 更新回到正确线程。
- [ ] 成功/失败/空输入/长输入均有测试。
