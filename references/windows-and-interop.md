## 窗口与组件

易语言窗口项目由设计器中的窗口/组件树和窗口程序集代码共同组成。组件属性、事件名称和支持库组件类型都依赖实际工程，不要凭常见名称创建不存在的属性或事件。

处理窗口任务时：

1. 读取对应窗口代码页和只读 XML/组件信息。
2. 搜索控件实例名及已有事件。
3. 查询组件所属支持库的公开接口。
4. 只修改代码页；需要新增/删除控件或改变布局时使用 IDE 设计器能力。

## 事件绑定

常见事件子程序名包含窗口或控件实例名，例如：

```text
.子程序 _按钮1_被单击
```

事件绑定可能依赖内部事件索引而不只是名字。不要把事件移动到普通程序集、其他窗口或类；不要在未同步设计器元数据的情况下随意重命名控件或事件。使用 AutoLinker MCP 时，可以修改已有控件事件子程序的代码实现，但新增事件子程序不代表已经建立控件事件绑定；新增、删除或修改事件绑定必须由用户在易语言 IDE 中完成。可把通用逻辑提取到全局唯一命名的普通子程序，再从原事件中调用。

## DLL 声明流程

调用 Win32 或第三方 DLL 前：

1. 确认目标平台位数、DLL 实际路径和导出入口名。
2. 从官方头文件/文档确认原型、调用约定、返回值和错误机制。
3. 映射每个 C 类型到当前易语言环境的确切宽度。
4. 明确参数是值、指针、输入输出缓冲区、字符串、结构体还是回调。
5. 确认 ANSI/Unicode 入口及字符串终止方式。
6. 写 `.DLL命令` 与 `.参数`，保留固定字段空槽。
7. 用最小输入测试成功、失败、空值和边界长度。

不要根据函数名猜 `A/W` 后缀、字符宽度或结构尺寸。

## 类型、指针与句柄

- 经典易语言 IDE 和许多支持库以 Win32/x86 为主，`整数型` 常被用于 32 位句柄或地址，但这不是跨位数保证。
- `HANDLE`、`HWND`、指针、`WPARAM/LPARAM`、`size_t` 等必须按目标 ABI 映射。目标变化时重新审查，不要默认都是整数型。
- `BOOL` 与易语言逻辑型/整数型的映射依赖声明方式和支持库约定；按实际接口验证。
- 指针指向的内存必须在调用期间有效；保存异步指针时要保证所有权和生命周期。
- 不把对象变量或文本变量的内部表示当成稳定的 C 结构。

## 文本编码

- `FunctionA` 通常接收本地代码页/ANSI 字符串；`FunctionW` 接收 UTF-16。
- 易语言文本如何传给 DLL 取决于运行库和声明桥接。确认现有封装或使用明确的编码转换与缓冲区。
- 缓冲区长度要区分字符数、字节数和是否包含终止符。
- 返回文本的 API 要明确由谁分配、谁释放以及缓冲区是否可写。
- 中文路径、页面名和 MCP JSON 传输使用 UTF-8 时，在本地 IDE/Win32 边界显式转换，避免把 UTF-8 字节当作 GBK/ANSI。

## 自定义数据类型与内存布局

使用 `.数据类型` / `.成员` 映射 C 结构时：

- 保持字段顺序，不按可读性重排。
- 核对每个字段宽度、有符号性、嵌套结构、固定数组长度和对齐。
- 区分内联数组与指针字段。
- 结构的 `cbSize`/`dwSize` 一类字段通常要填实际字节数。
- `union`、位域、可变长度尾数组和平台相关对齐不能用普通字段列表盲目映射；优先使用成熟支持库封装或字节集手工编解码并写测试。

## 分层窗口与 GDI/GDI+ 画板

需要逐像素透明、阴影或自绘内容时，可把顶层窗口设为 `WS_EX_LAYERED`，使用内存 DC 作为 GDI/GDI+ 画板，再通过 `UpdateLayeredWindow` 提交到窗口。先确定窗口更新模式：逐像素 alpha 使用 `UpdateLayeredWindow`；整窗透明度或颜色键使用 `SetLayeredWindowAttributes`。同一窗口不要在两种模式间随意混用，修改 layered 状态后要重新建立绘制路径。

推荐的初始化和绘制顺序如下：

1. 保留窗口原有扩展样式后设置 `WS_EX_LAYERED`。在可移植代码中使用指针宽度的窗口样式 API，不要把 `LONG` 地址参数硬编码成 32 位整数。
2. 初始化 GDI+，保存启动令牌；通常按进程或共享上下文初始化一次，所有 `Graphics`、图像和画刷销毁后再关闭。
3. 获取目标 DC，创建兼容内存 DC 和 32 位 `DIBSection`。使用带 alpha 的像素格式（通常为 BGRA），优先使用负高度的 top-down DIB，避免上下方向反转；校验宽高乘积，防止整数溢出。
4. 将 DIB 选入内存 DC 并保存旧位图句柄。用 `GdipCreateFromHDC` 创建 `Graphics`，先以全透明色清空画布，再绘制背景、图像、路径或文字。
5. 准备目标位置、源位置、尺寸和 `BLENDFUNCTION`，将 `SourceConstantAlpha` 设为需要的全局 alpha，并设置 `AC_SRC_ALPHA`。调用 `UpdateLayeredWindow` 提交内存 DC；检查返回值，失败时立即保留错误上下文。

`UpdateLayeredWindow` 的源像素必须符合预乘 alpha 约定：每个颜色通道已经乘以该像素的 alpha。不要只写 RGB 而留下未初始化的 alpha；也不要假设普通 `FillRect` 会可靠地把 DIB 的 alpha 通道清零。可用 GDI+ 的透明 `Clear`、源复制合成模式或显式清零像素完成清屏；对外部图像必要时转换为 32bpp ARGB 并验证边缘像素，避免黑边和半透明颜色溢出。若需要整体淡入淡出，可使用颜色矩阵调整 alpha，但仍要保持预乘结果。

加载文件或内存图像时，确认字符串编码和 `A/W` 入口；从 `IStream` 加载的图像必须在图像销毁前保持流和其后备内存有效，不能在调用返回后立即释放。每个 GDI、GDI+、COM 流和内存对象都要记录所有权、成功标志和匹配的释放函数。

按反向顺序清理：停止重绘并解除仍可能访问画板的回调或线程，销毁 `Graphics`、图像、画刷、画笔和字体，恢复内存 DC 中的旧位图，再删除 DIB，删除内存 DC，释放目标 DC，最后在全局无使用者时关闭 GDI+。中途任一步失败都应执行已完成步骤的回滚，并在释放后清零句柄，避免重复释放；不要在位图仍被 DC 选中时删除它。

声明 Win32、GDI+ 和 COM 接口时重新核对目标 x86/x64 的结构对齐、句柄/指针宽度、`BOOL`、`HRESULT`/状态码和调用约定。窗口尺寸改变时重新分配画板并提交一次完整更新；绘制失败、空图像、尺寸为零和超大尺寸都应有明确的失败路径。

## 回调

- 使用 `&回调子程序` 取得地址；需要数值地址时按当前平台使用已验证的转换。
- 回调的参数、返回值和调用约定必须与原生声明完全一致。
- 回调期间不要让承载代码或相关对象提前销毁。
- 原生线程触发的回调不能直接操作非线程安全的 IDE/UI 对象；把数据投递回主线程。
- 捕获回调上下文时使用显式句柄或索引，不假设存在闭包。

## 类方法回调与实例绑定

原生 API 通常只接收裸函数地址；裸地址不能自动携带某个类实例。类成员子程序也不应被假定可以直接写成 `&类方法` 并符合原生回调 ABI。按以下顺序选择方案：

1. API 提供 `user_data`、`context`、`lParam` 等上下文参数时，传入稳定句柄或索引，由普通程序集回调查表取得实例。
2. API 没有上下文参数但提供窗口句柄、对象句柄或注册标识时，使用受同步保护的显式映射，并在注销时删除映射。
3. 只有前两种方式不可用，且已固定经典 Win32/x86 编译器与 ABI 时，才考虑为实例动态生成回调跳板。

某个历史类回调模块采用过第三种方案：读取特定编译器的类对象和方法表，生成一段包装代码，复制原回调参数，按该编译器的隐藏实例参数形式加入对象上下文，再跳转到类方法；方法返回后由公共清理跳板恢复栈、非易失寄存器和部分浮点状态。完整机制与审查要求见 [embedded-machine-code.md](embedded-machine-code.md)。

不要从这个案例推导通用类 ABI。对象内部布局、方法表序号、隐藏实例参数、`EBP` 链、每参数 4 字节和清栈方式都可能随 IDE、普通/静态编译、优化或第三方后端变化。外部回调的 `cdecl`/被调方清栈约定与易语言类方法自身的调用约定是两个独立边界，必须分别验证。

管理动态跳板时使用明确所有权：保存回调地址和关联实例，先从原生 API 注销回调，再阻止新调用并等待正在执行的回调退出，最后释放可执行内存和映射。不得在实例销毁时直接释放仍可能被其他线程调用的跳板。

## 线程与生命周期

- 支持库可能提供线程、同步、网络或异步命令，这些是依赖 API，不是语言固有能力。
- UI 对象通常只能由创建它的线程访问。
- 共享全局变量和类实例需要同步；先搜索项目既有锁或消息机制。
- DLL 返回的句柄、内存、窗口、文件和网络对象必须走匹配的释放函数。
- `_销毁`、窗口销毁事件或程序退出路径应解除回调、停止工作线程并释放资源。

## 互操作检查表

- [ ] 位数与调用约定正确。
- [ ] DLL 名和入口名真实存在。
- [ ] 返回值、错误码及 `GetLastError` 使用时机正确。
- [ ] 所有参数宽度、方向和可空性正确。
- [ ] 文本编码、缓冲区单位和终止符正确。
- [ ] 结构大小、对齐、数组和嵌套布局正确。
- [ ] 指针、回调和异步数据生命周期正确。
- [ ] 动态回调跳板已先注销并等待在途调用结束，再释放可执行内存。
- [ ] UI 更新回到正确线程。
- [ ] 成功/失败/空输入/长输入均有测试。
