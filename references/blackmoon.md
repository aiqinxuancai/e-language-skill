## 定位与证据边界

先区分两个层次：黑月编译是后端工具链，黑月界面类是提供 UI 对象的易模块；引入界面模块不等于已经使用黑月后端编译。典型安装包含：

- `BlackMoon.fne`：接入易语言 IDE 的编译插件。
- `BlackMoon/bin/RC.EXE`、`CVTRES.EXE`、`LINK.EXE`：资源和链接工具。
- `BlackMoon/lib/BlackMoonExe.obj`、`BlackMoonDll.obj` 等：不同输出类型的启动对象。
- `BlackMoon/lib/*.lib` 与 `krnln.lib`：核心和 Win32 导入库。
- 黑月界面类、黑月核心库等 `.ec`：建立纯代码 Win32 界面的易模块，不是编译器本身。

当前已核实发行版的编译命令包含 `/machine:I386` 和 `CVTRES /MACHINE:IX86`，按 x86 验证；遇到其他发行版时必须读取实际命令和对象库，不要把该结论推广到所有黑月版本。

证据优先级固定为：当前工程依赖和可编译示例 > 当前版本模块公开接口 > 当前黑月安装/编译日志 > 旧教程。不得仅凭网络文章发明类名、方法名或参数。

## 先识别 API 家族

黑月相关模块存在多个不兼容代际，先按下表识别，不要混用签名：

| 模块家族 | 常见接口形态 | 兼容规则 |
| --- | --- | --- |
| `黑月界面类` 3.x | `应用程序类`、`窗口类`、`对话框类`、控件类、布局类 | 以当前 3.x 模块公开接口为准 |
| `黑月类模块` 2.x | 可能使用 `对话框类.载入 (父窗口, 资源ID, 回调)` | 不能套用到 3.8/3.9 |
| 更早的 `黑月模块` | `黑月_初始化`、`DialogBoxParam`、`LoadIcon` 等低层封装 | 不属于现代界面类抽象 |
| `黑月核心库`、`黑月扩展模块`、第三方改版 | 由具体发行版决定 | 必须读取本地公开声明和示例 |

若有 `.e/.ec` 而无可靠文档，按 [e-packager.md](e-packager.md) 解包并检查：

1. `project/.module.json` 中实际依赖名和原路径。
2. 模块工作区的 `header/header.txt`，确认公开类、子程序、参数和常量。
3. 可运行示例的 `src/*.txt`，确认调用顺序、事件签名和生命周期。

始终针对项目实际依赖生成代码。不要为了让示例“看起来现代”而静默升级模块。

## 程序入口与工程类型

黑月界面类程序的默认入口是普通程序集中的 `_启动子程序`。`应用程序类.初始化` 和 `应用程序类.运行` 都属于此入口，不属于易语言可视化窗口事件。

新建工程时按以下步骤搭建入口：

1. 在 IDE 中新建 **Windows 窗口程序**（黑月编译需要窗口程序而非控制台程序的工程类型和子系统设置）。
2. 删除默认生成的 `_启动窗口` 窗口程序集。只要工程里还存在名为 `_启动窗口` 的窗口，易语言就会优先载入它并无视 `_启动子程序`，黑月界面代码不会被执行。
3. 在任意普通程序集中手动新增 `_启动子程序`（新建窗口程序时 IDE 不会生成它）。
4. 在 `_启动子程序` 中初始化 `应用程序类`、创建黑月窗口，并以 `应用程序类.运行` 提供消息循环。

```text
.版本 2

.程序集 程序集1

.程序集变量 App, 应用程序类
.程序集变量 mainFrame, 窗口类

.子程序 _启动子程序, 整数型

App.初始化 ()
mainFrame.事件_创建完毕 (&mainFrame_创建完毕)
.如果真 (mainFrame.创建 (, “黑月窗口”) == 假)
    返回 (-1)
.如果真结束
返回 (App.运行 (mainFrame))
```

### 入口禁止事项

- 不要在 `__启动窗口_创建完毕` 或其他易语言可视化窗口事件中初始化 `应用程序类` 或调用 `运行`；这会嵌套消息循环。
- 代码入口方案必须删除或改名 `_启动窗口`，再新增 `_启动子程序`。
- 如果保留易语言可视化窗口作为主界面，就使用易语言自身的窗口体系，不要再引入 `应用程序类.运行`。

判断已有工程时按以下顺序：`_启动窗口`（存在则优先载入）→ `_启动子程序`（代码入口）→ DLL 的 `Dll入口函数`。通用入口规则见 [language-basics.md](language-basics.md) 的「程序入口」。

## 编译与链接模型

典型黑月 EXE 流程：易语言代码 → 黑月启动对象/核心对象 → 同名 RC 编译为 `.res` → `CVTRES` → `LINK` 输出 PE。已观察到的链接入口选项为 `/ENTRY:BMEntrypoint`，目标为 I386。

### 编译前确认

1. IDE 已加载与当前易语言版本匹配的 `BlackMoon.fne`。
2. 黑月目录中的 `bin`、`lib`、启动对象和 `krnln.lib` 完整。
3. 工程输出类型是 EXE、DLL 还是资源 DLL；不同类型使用不同启动对象和入口约定。
4. 所用支持库具有黑月可链接的静态库或兼容实现。IDE 中能识别命令不代表黑月链接一定成功。
5. 当前编译命令确实是“黑月编译”，不要用普通编译或静态编译结果代替验证。

### 错误定位

遇到未解析外部符号时，先定位命令来自哪个支持库，再检查对应 `.lib`、目标位数和调用约定；不要通过删除调用掩盖依赖不兼容。

## 创建并嵌入 RC

黑月会在易语言源文件旁查找同基本名的 RC。插件二进制中可见 `%s.rc`，本地示例也使用 `test.e + test.rc`、`ComObjectView.e + ComObjectView.rc`。按以下规则创建：

1. 先保存工程，例如 `Demo.e`。
2. 在同一目录创建 `Demo.rc`，基本名必须一致。
3. 可用 `BlackMoon/bin/ResEd.exe` 新建和编辑，也可用可靠的 Win32 资源编辑器或文本编辑器。
4. 在 RC 中定义对话框、控件、图标、菜单、字符串表、清单或 `RCDATA`。
5. 在易语言工程中另建数值完全一致的常量。RC 的 `#define` 不会自动成为易语言 `#常量`。
6. 用黑月编译，确认日志中 RC 被编译为 `.res`，再经 `CVTRES` 转为可链接资源。

最小 RC 示例：

```rc
#define IDD_MAIN 1000
#define IDC_OK 1001
#define IDR_MANIFEST 1

LANGUAGE 4,2

129 ICON DISCARDABLE "res/icon.ico"

IDD_MAIN DIALOGEX 10,10,240,120
CAPTION "黑月窗口"
FONT 9,"宋体",0,0,0
STYLE 0x10CF0800
BEGIN
  CONTROL "确定",IDC_OK,"Button",0x50010000,90,88,60,18
END

IDR_MANIFEST MANIFEST "xpmanifest.xml"
```

注意：

- 相对资源路径必须能从 RC 编译时的工作目录解析。最稳妥的布局是把资源放在工程旁的 `res` 子目录，并保持示例实际编译通过。
- 老版 RC 工具对编码敏感。本地带中文示例使用 GBK/CP936；使用 UTF-8 前必须用当前 `RC.EXE` 实测，不能只看编辑器显示正常。
- `DIALOG/DIALOGEX` 的坐标单位是对话框单位，不等同于像素。
- OCX 示例的 RC 类名可能是 `AtlAxWin`。这还要求控件已按目标位数注册，并且应用初始化了 ATL 容器。

## 从 RC 创建窗口并绑定控件

现代黑月界面类 3.x 的非模态主对话框模式：

```text
.程序集变量 app, 应用程序类
.程序集变量 main, 对话框类
.程序集变量 okButton, 按钮类

.子程序 _启动子程序, 整数型

app.初始化 ()
main.事件_创建完毕 (&main_创建完毕)
.如果真 (main.创建自资源 (, #IDD_MAIN) == 假)
    返回 (-1)
.如果真结束
app.运行 (main)
返回 (0)

.子程序 main_创建完毕
.参数 hWnd, 整数型

okButton.绑定 (main, #IDC_OK)
okButton.事件_被单击 (&okButton_被单击)

.子程序 okButton_被单击
.参数 hWnd, 整数型
.参数 id, 整数型

main.销毁 ()
```

关键顺序是：初始化应用 -> 注册创建事件 -> 从资源创建 -> 在创建回调中绑定子控件 -> 注册子控件事件 -> 进入消息循环。这一整条链的起点同样是 `_启动子程序`，不是易语言可视化窗口事件。

对现代 3.x API：

- `创建自资源` 创建非模态对话框，主窗口需要 `应用程序类.运行` 提供消息循环。
- `载入自资源` 载入模态资源对话框并返回对话框结果。
- `绑定 (父窗口或句柄, 控件ID)` 只包装 RC 已创建的子窗口，不会创建新控件。
- 旧 `黑月类模块` 可能把资源 ID 和创建回调直接放进 `载入`；只有当前模块头确有该签名时才这样写。

若 `创建自资源` 失败，依次检查同名 RC 是否进入输出、`IDD_*` 数值是否一致、实例句柄是否正确、资源是否真的是对话框类型。若 `绑定` 失败，检查它是否在父窗口创建完成后执行，以及 `IDC_*` 是否属于该对话框。

## 纯代码黑月窗口

纯代码窗口不依赖易语言可视化窗口页，也不要求 RC 对话框。按[程序入口与工程类型](#程序入口与工程类型)搭好 `_启动子程序` 后，使用黑月界面类对象直接创建原生窗口和控件：

```text
.版本 2

.程序集 程序集1

.程序集变量 App, 应用程序类
.程序集变量 mainFrame, 窗口类
.程序集变量 layout, 布局线性类
.程序集变量 buttons, 按钮类, , "0"

.子程序 _启动子程序, 整数型

App.初始化 ()
mainFrame.事件_创建完毕 (&mainFrame_创建完毕)
mainFrame.边框 (#窗口边框_普通可调边框)
.如果真 (mainFrame.创建 (, “纯代码黑月窗口”) == 假)
    返回 (-1)
.如果真结束
返回 (App.运行 (mainFrame))

.子程序 mainFrame_创建完毕
.参数 hWnd, 整数型
.局部变量 i, 整数型

layout.模式 (#线性布局模式_垂直)
重定义数组 (buttons, 假, 5)
.计次循环首 (取数组成员数 (buttons), i)
    buttons[i].创建 (mainFrame, “按钮” + 到文本 (i))
    layout.插入项目 (i - 1, buttons[i], 0, 黑月矩形 (5, 5, 5, 5), )
.计次循环尾 ()
mainFrame.置布局 (layout)
```

这里易语言数组索引从 1 开始，而该版本布局项目位置使用从 0 开始的索引，所以示例传 `i - 1`。不要把这个差异推广到未核实的其他集合 API。

也可把创建主窗口封装为返回 `窗口类` 的子程序，再调用 `App.运行 (启动窗口_创建 ())`。无论采用哪种形式，都要检查创建返回值并保证返回对象仍然存活。

## 对象、事件与布局规则

### 创建与生命周期顺序

1. 将主窗口、控件、布局和长期资源声明为程序集变量或全局变量，避免局部包装对象过早销毁。
2. 在 `创建`、`创建自资源` 或 `载入自资源` 前注册 `事件_创建完毕`。
3. 在黑月窗口自己的 `事件_创建完毕` 中创建/绑定子控件；此时父窗口句柄才有效。
4. 控件创建或绑定后立即注册控件事件，并严格按当前模块头填写回调参数。
5. 可调窗口使用布局类（或尺寸事件）处理缩放，不要只按初始尺寸摆放。

### 必须避免

- 整个程序只保留一个消息循环，由 `_启动子程序` 中的 `应用程序类.运行` 提供；不要在窗口/控件事件或 `__启动窗口_创建完毕` 中再次调用。
- UI 创建、绑定、销毁和消息处理留在创建窗口的线程；后台线程通过消息或已验证的线程切换机制更新 UI。
- 窗口、控件、数组包装对象和 GDI/GDI+ 资源按稳定所有权顺序销毁；不要在“将被销毁”事件中提前删除仍会访问的窗口变量。
- `创建W`、`载入W` 等接口通常接收 Unicode 字节集；非 `W` 接口的转换行为必须以当前模块签名和实现为准。

## 黑月界面类 + Masonry 约束布局使用方法

本节只适用于用户提供的 `黑月界面类3.9.6-Masonry约束布局-beta.2.e`（或接口完全一致的改版）。标准版 `黑月界面类 3.9.6` 未确认包含这些命令时，不要直接套用。

父窗口设置为约束布局后，在父窗口创建完成、子控件句柄有效时，为每个控件建立并安装约束：

```text
.局部变量 make, 约束制造器

main.布局类型 (#布局类型_约束)

make.制造 (按钮1)
make ＝ make.左 ().等于 (main.左 ()).偏移 (12)
make ＝ make.顶 ().等于 (main.顶 ()).偏移 (10)
make ＝ make.宽 ().等于值 (160)
```

常用调用方式：

- `制造 (控件)` 新建约束；已有约束可用 `更新 (控件)` 修改，或用 `重建 (控件)` 清空后重建。
- 属性链使用 `左`、`右`、`顶`、`底`、`宽`、`高`、`中心X`、`中心Y`；每次链式调用都把返回值重新赋给 `make`。
- 参照控件使用同名锚点，例如 `make.右 ().等于 (面板1.左 ())`；关系还可用 `大于等于`、`小于等于`。
- 固定尺寸或位置使用 `等于值 (数值)`，也可用 `大于等于值`、`小于等于值`。
- `偏移 (数值)` 接受有符号整数；`倍率 (数值)` 使用千分比，`1000` 表示 `1.0`、`500` 表示 `0.5`、`333` 约表示三分之一。
- 每组约束最后调用 `安装()`；窗口可调大小时，约束布局会随父窗口尺寸变化重新布局。

## DLL 项目

黑月 DLL 使用公开的 `Dll入口函数` 约定，参数对应实例句柄、调用类型和保留值：

```text
.子程序 Dll入口函数, 逻辑型, 公开
.参数 DLL实例句柄, 整数型
.参数 调用类型, 整数型
.参数 保留, 整数型

.判断开始 (调用类型 == 1)
    全局_实例句柄 = DLL实例句柄
.默认
.判断结束
返回 (真)
```

在入口中只保存句柄和做必要的轻量初始化，不要在加载器锁内显示窗口、等待线程或执行复杂 COM 工作。真正创建 UI 时调用 `应用程序类.初始化 (全局_实例句柄)`，否则资源函数可能错误地从宿主 EXE 而非 DLL 查找资源。

DLL 内显示模态窗口时通常不需要主 EXE 式的长期 `App.运行`；非模态窗口则必须明确由谁提供消息循环和对象生命周期。以当前项目调用场景验证，不要复制 EXE 模板后直接导出。

## 其他资源与 XML

现代黑月界面类还可能提供：

- `黑月寻找资源ID/黑月寻找资源名`：按 ID 或名称调用 `FindResource`，默认资源类型通常是 `RT_RCDATA`。
- `黑月取资源字节集`：通过 `SizeofResource/LoadResource/LockResource` 复制资源内容。
- `位图类.创建自RC资源`、`菜单类.载入RC资源`、`zyString.添加RC资源` 等类型化接口。
- `zyXML资源类`、窗口或控件的 `创建自XML`：从 XML 创建窗口、控件、菜单、图像等。

调用资源辅助函数前确认资源类型。例如 MANIFEST 是 24，`RCDATA` 是 10；找到错误类型会返回 0。`zyString.添加RC资源` 在已核实版本中实际调用 `LoadString`，它读取的是字符串表，不是任意 `RCDATA`。

XML 能减少 RC 对话框模板依赖，但其标签、属性和编码随黑月界面类版本变化。必须读取当前版本公开接口和可运行 XML 示例，不能根据新版格式猜旧版。

## 排错与验证

按以下顺序验证黑月项目：

1. 解包或读取工程依赖，确认黑月模块家族和版本。
2. 确认入口：工程内不存在 `_启动窗口`，`应用程序类` 的初始化与 `运行` 都在 `_启动子程序` 中，且没有任何易语言窗口事件参与启动链。
3. 搜索模块公开接口，核对每个类名、方法名、参数顺序、可空性和回调签名。
4. 确认 `.e` 与 `.rc` 同目录同基本名，RC 引用文件存在，中文编码可被当前 `RC.EXE` 解析。
5. 确认易语言常量值与 RC `#define` 一致且没有重复冲突。
6. 执行黑月编译，保存完整输出；分别识别易语言生成错误、RC 错误、CVTRES 错误和 LINK 错误。
7. 检查输出 PE 中是否存在预期的 DIALOG、ICON、MANIFEST、MENU 或 RCDATA 资源。
8. 启动程序，验证主窗口创建、子控件绑定、事件触发、缩放布局和关闭退出。
9. DLL 还要从真实宿主加载，验证实例句柄、导出函数、资源查找和卸载。
10. OCX/COM 控件要在干净环境验证注册状态、x86 位数和 ATL 初始化。

编译成功不是 UI 完成条件。至少实际触发一次创建事件、一个控件事件、窗口缩放和正常关闭；资源或 DLL 项目还要覆盖资源读取/宿主加载路径。

## 常见错误

- 把黑月界面类当成黑月编译器，或只引入模块却仍用普通编译验证。
- 在 `__启动窗口_创建完毕` 或其他易语言可视化窗口事件中初始化 `应用程序类` 并调用 `运行`，在原生窗口内部再套一层消息循环。
- 保留默认的 `_启动窗口` 却期望 `_启动子程序` 执行，或新建窗口程序后忘记手动添加 `_启动子程序`。
- 混用 `黑月类模块` 2.x、`黑月界面类` 3.x 和第三方改版的同名方法。
- `.rc` 与 `.e` 不同名、不同目录，或资源相对路径在编译工作目录下不存在。
- 认为 RC 的 `#define` 会自动同步成易语言常量。
- 中文 RC 保存为当前老版 `RC.EXE` 不支持的编码，造成乱码或语法错误。
- 把现代 `载入自资源` 写成旧版 `载入`，或把内存创建接口当作 RC 接口。
- 在父窗口创建前绑定控件，或在窗口创建后才注册创建完毕事件。
- 忘记 `应用程序类.初始化`、主窗口消息循环，或让主窗口/控件对象过早离开作用域。
- DLL 未把实例句柄传给应用初始化，导致从宿主 EXE 查找资源。
- 在 `Dll入口函数` 中创建 UI、等待线程或执行重型初始化。
- 忽略 x86 限制、OCX 注册位数、支持库静态库缺失或调用约定差异。
- 把文本型、Unicode 字节集和裸指针混用，尤其是在 `W` 接口和回调中。
