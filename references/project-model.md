## 文件与扩展机制

- `.e`：易语言工程，包含代码、窗口、资源、依赖和编辑信息的二进制文件。
- `.ec`：易模块，主要由易语言代码组成并公开可复用接口；格式与 `.e` 相近，但用途是依赖模块。
- `.fne` / `.fnr`：支持库的动态形态，实质通常是按易语言支持库 ABI 导出的 DLL。
- `.lib`：支持库或原生代码的静态链接产物，具体使用方式取决于支持库构建方案。

模块和支持库不可混为一谈：模块是易语言代码工具箱；支持库由 C/C++ 等实现，用于增加命令、数据类型或组件。调用支持库的 `GetNewInf()` 可获得其公开元信息。外部 Agent 应通过 IDE/AutoLinker 的依赖查询能力，或当前工作区已经导出的公开接口确认实际 API。

## 程序入口与输出类型

`_启动子程序` 是易语言的标准入口，相当于 C/C++ 的 `main`，写在普通程序集中。但它不一定是当前工程的实际入口：工程中存在名为 `_启动窗口` 的窗口时（IDE 新建窗口程序的默认状态），程序直接优先载入该窗口并无视 `_启动子程序`。把 `_启动窗口` 改名并新增 `_启动子程序`，再在其中显式 `载入 (窗口, , 假)`，即可把入口改为代码驱动。语法细节与示例见 [language-basics.md](language-basics.md) 的「程序入口」。

因此判定入口时至少确认三件事：

- 是否存在 `_启动窗口` 窗口程序集。
- 普通程序集中是否存在 `_启动子程序`，以及它是否真的会被执行。
- 工程输出类型是窗口 EXE、控制台 EXE、DLL 还是易模块（`.ec`）；不同输出类型的入口约定不同。

易模块（`.ec`）也可以包含 `_启动子程序`。被主工程引用时它一般不作为主程序入口执行，模块的对外能力仍由公开子程序决定；把模块工程显式编译为控制台 EXE 时该入口会执行，可用于模块自测。DLL 工程另有入口约定（黑月 DLL 为 `Dll入口函数`）。

## 页面与名称解析

易语言源码由 IDE 程序树中的程序项组织。一次修改前先确定：

- 目标程序项对应普通程序集、类还是窗口程序集。
- 目标子程序是否在该页面。
- 普通/窗口程序集是否已有同名子程序。
- 目标项是否属于全局变量、常量、自定义数据类型、DLL 命令等固定表。

普通程序集和窗口程序集的子程序名称通常全工程可见。新增、移动或改名前执行全工程搜索。类方法通过对象调用，但仍应检查公开属性及与依赖接口的冲突。

页面头部可能包含 `.版本`、`.支持库`、程序集/窗口程序集标识和 IDE 版本相关的隐藏信息。`.支持库` 行决定当前页可见的扩展命令、类型和组件；不要为了让某个命令“看起来可用”手工添加同名支持库。先确认安装库、版本和用户是否允许改变依赖。

工程还可能保存编译条件、平台/输出类型和条件编译相关元数据。条件编译符号不是普通变量，分支中的代码可能只在特定构建配置存在；排错时确认当前实际配置，不要把未启用分支当作运行代码。

## 类和窗口程序集

类：

- `.程序集` 头部可包含基类和公开属性。
- `.程序集变量` 是实例状态。
- `_初始化`、`_销毁` 是生命周期入口，保留 IDE 生成的结构。
- 不假设支持重载、覆盖、接口多态、静态类或类内单例。
- 需要全局唯一对象时，按项目习惯在全局变量表声明实例，并审查初始化时序。

窗口程序集：

- 窗口设计信息与窗口程序集代码共同构成功能。
- 控件事件名与窗口/控件绑定，例如 `_按钮1_被单击`；移动、改名或复制事件都可能破坏绑定。
- 窗口界面定义与窗口程序集代码是不同程序项。界面布局和控件树变更优先通过 IDE 设计器完成。
- 不在工作线程直接操作窗口控件；通过窗口消息或项目既有的主线程调度方式更新 UI。

## 依赖发现

调用陌生命令前按以下顺序搜索：

1. 当前工程是否有同名子程序。
2. 已导入易模块的公开接口。
3. 已加载支持库的公开接口。
4. AutoLinker 的模块/支持库搜索工具。
5. 可靠文档或原始头文件。

确认命令的返回类型、参数数目与顺序、空参数意义、参考/数组/可空属性及副作用。不同支持库可能提供同名命令，不要仅凭命令名确定来源。

只有用户明确要求时才新增、删除或刷新模块/支持库。引入依赖会改变工程元数据、部署文件和编译结果，不是普通源码修改。

## 资源与元数据

- 资源通过 `#名称` 引用；重命名时同步代码引用和资源索引。
- 易语言工程可保存图片、声音、长文本及其他二进制常量资源；资源不仅是磁盘文件，还包含名称、公开属性和工程内索引。
- 不用普通二进制编辑器修改 `.e/.ec` 内部资源、依赖记录或编辑信息。
- 模块公开资源和主工程私有资源的可见性不同，引用前确认是否公开及是否随产物部署。

## 安全编辑边界

- 修改业务代码：通过 IDE、AutoLinker 真实页工具或明确支持文本回包的第三方工具。
- 修改窗口布局：优先 IDE 设计器；不要猜测 XML schema。
- 修改固定表：使用对应 IDE 程序项/API，避免整表覆盖长文本或二进制常量。
- 修改依赖：使用 IDE 或明确支持依赖管理的工具，不要把公开接口文本当作依赖声明修改。
- 修改二进制 `.e/.ec`：使用经过验证的打包器或 IDE，不用十六进制替换。
