## 需求分析

先把任务分类为：局部逻辑修改、跨程序集功能、窗口事件、类接口、依赖调用、DLL 互操作、资源/固定表、构建配置或语言迁移。分类决定必须读取的页面、依赖和验证方式。

记录不变量：已有公开接口、事件名称、参数属性、返回语义、错误约定、线程要求、支持的 Windows 版本和目标位数。不要在“优化”时悄悄改变这些契约。

## 代码探索

从符号而不是文件猜测开始：

1. 搜索目标子程序、调用者、共享变量、事件和资源名。
2. 读取完整代码项及相邻程序集变量。
3. 搜索依赖命令的公开定义。
4. 检查同名子程序与类公开性。
5. 修改公共接口前读取所有调用点。

不要只读当前光标附近几行。也不要无目的读取整个大型工程；优先批量搜索，再读取影响正确性的范围。

## 实现策略

- 局部行为修复：最小精确编辑，保留函数签名和页面。
- 大块函数重写：基于完整真实函数/页面生成一次替换，避免多轮脆弱补丁。
- 公共逻辑复用：新增全工程唯一的子程序名，并更新明确调用点。
- 窗口事件：保留事件壳，将可复用逻辑提取到普通子程序，但事件仍留在原窗口页。
- 类：区分公开 API 与私有辅助方法；保留生命周期函数。
- 未知支持库能力：先查接口；没有可靠命令时用已存在的低层 API 组合，或向用户说明需要新增依赖。

## 编译错误分类

按最先出现的根因处理：

- 找不到命令/子程序：拼写、依赖未导入、公开性、模块版本或名称冲突。
- 参数数目/类型错误：读取真实签名，特别检查空槽、参考、数组和可空属性。
- 变量/类型不存在：声明顺序、作用域、固定表、类成员或支持库类型。
- 控制流错误：开始/结束指令不配对，`.如果真` 混入 `.否则`，判断/循环交叉闭合。
- 声明格式错误：中间空槽丢失、说明挤入属性字段、执行语句后声明变量。
- DLL/链接错误：目标位数、入口名、静态/动态支持库、输出类型或部署文件。
- 窗口事件错误：控件/窗口名变化、事件页错误或设计器元数据不一致。

修复第一组错误后重新编译；后续错误可能只是级联结果。

## 运行期排错

- 先建立稳定复现步骤和输入。
- 检查返回值、错误码和日志，不用无依据的延时规避竞态。
- 对数组检查空数组、1 基索引和重定义后的成员数。
- 对文本检查空文本、中文编码、字节/字符长度和缓冲区终止符。
- 对窗口检查线程、句柄有效期、销毁顺序和消息时序。
- 对 DLL 检查 ABI、内存所有权、结构大小、回调存活期。
- 对模块/支持库检查开发环境与编译产物部署的版本是否一致。

如果多轮局部补丁反复产生新问题，停止叠加补丁，重新审视状态所有权、页面职责、全局变量、异步生命周期或互操作封装设计。

## 代码审查与优化

优先检查行为风险：

- 越界、空值、错误返回未处理。
- 全局状态和静态局部变量造成的重入问题。
- 事件、线程、回调中的对象生命周期。
- DLL 句柄和内存未释放。
- 重复子程序名、错误公开性和意外 API 变化。
- 编造或误用支持库命令。

优化时保持易语言习惯：减少重复搜索/转换、避免循环内不变工作、批量处理数组和文本，但不要为了“现代化”引入语言不支持的抽象。性能结论需要测量；可读性优化不得改变参数副作用和错误语义。

## 测试策略

至少覆盖：

- 正常输入。
- 空文本、空数组、零值和可空参数。
- 最小/最大边界、中文和特殊字符。
- 失败返回、文件不存在、网络超时、DLL 加载失败。
- 重复调用、窗口关闭、线程取消和程序退出。

纯解析/转换逻辑可放到独立测试程序验证；依赖 IDE 页面、控件、编译器和支持库加载的行为必须在真实易语言 IDE 环境测试。

最轻量的可运行验证手段是标准入口加控制台输出：在 `_启动子程序` 中调用待验证子程序，用 `标准输出` 打印输入与结果，显式编译为控制台 EXE（必要时静态编译）后运行产物并读取 stdout。易模块（`.ec`）也包含 `_启动子程序`，验证模块逻辑时同样显式编译为控制台 EXE，不要编译为模块——那样入口不会执行。入口没有执行时先确认工程中是否存在 `_启动窗口` 抢占了入口，见 [language-basics.md](language-basics.md) 的「程序入口」。验证代码属于调试脚手架，完成后还原或明确告知用户。

## 迁移到其他语言

迁移不是逐词翻译。建立映射清单：

- `.程序集`/类/窗口页到目标模块或类。
- 子程序、参数属性和数组输出到目标函数签名。
- 全局变量和程序集变量到明确状态所有者。
- 支持库命令到目标平台 API。
- 窗口控件/事件到目标 UI 框架。
- DLL 声明、自定义结构、回调到目标 FFI。
- 资源常量和模块依赖到目标资源/包系统。

先写行为测试或输入输出样例，再逐模块迁移。保留 1 基数组、空参数、副作用、编码和错误返回等原语义，之后才做目标语言重构。

## 从其他语言迁入

先去除目标语言特有机制：异常、泛型、异步/等待、闭包、继承多态、重载、RAII、垃圾回收假设。为每项选择易语言可验证的显式实现：状态码、输出参数、类/程序集变量、消息回调、支持库线程 API 或 DLL 封装。

不得把目标语言函数名翻译成一个未经搜索的中文命令。已有支持库无对应能力时，明确实现封装、声明 DLL 或新增依赖的成本。
